# 思屿：AI 对话、感思与个人知识沉淀平台

**产品设计文档 / Product Design Document**  
版本：1.0  
日期：2026-08-12  
状态：设计基线已确认  

---

## 文档摘要

“思屿”是一款个人优先、可扩展为多用户服务的 AI 深度思考与知识沉淀产品。产品以“议题”为起点，将每日议题推荐、自建议题、多模型对话、私人旁注、独立感思、结构化纪要、可追溯的推理摘要、思维导图、知识检索与多格式导出连接为一条完整链路。

核心价值不是提供另一个聊天窗口，而是让一次 AI 对话从临时交流转化为可搜索、可关联、可回顾、可迁移的个人思想档案。

### 已确认的关键决策

- 产品形态：个人优先，数据和权限架构支持未来多用户。
- 模型接入：平台模型与用户自带 API Key 的混合模式；第一期优先平台统一接入。
- 每日议题：热点、个性化、随机思想题三类并行，并支持自建议题。
- 思考过程：记录可读的推理摘要与观点演变，不展示或声称展示模型隐藏思维链。
- 感思结构：会话旁注与独立感思并存，历史内容仅在用户授权后用于分析。
- 存储策略：云端加密同步、本地草稿缓存、完整备份和彻底删除。
- 导出：Markdown、PDF、JSON 优先；Word、PNG、SVG 后续增强。
- 产品方案：采用“思考工作台型”，当前不建设公开社区。

# 1. 产品愿景与范围

## 1.1 产品定位

思屿面向希望通过 AI 进行长期学习、观点梳理、深度讨论和自我反思的个人用户。产品围绕“议题—讨论—感思—整理—回顾”构建，不将消息数量或连续打卡作为核心指标。

产品希望解决四个问题：

1. 每天不知道值得深入讨论什么；
2. 与 AI 的对话容易淹没在历史消息中；
3. 临时想法、旁注和正式感思彼此分散；
4. 对话结束后缺少可验证、可导出、可长期回顾的成果。

## 1.2 核心设计原则

1. **以议题组织思考。** 对话、旁注、资料、纪要和导图均围绕议题聚合。
2. **区分原始内容与 AI 产物。** 用户原文、AI 回复、AI 整理稿和用户修订稿均有明确来源与版本。
3. **可追溯而非伪造确定性。** 纪要重点可返回原始依据；综合判断必须标注“综合推断”。
4. **默认最小授权。** 私人旁注和历史内容不默认进入模型上下文。
5. **数据可带走。** 用户能导出、备份和删除自己的全部内容。
6. **先闭环，后智能化。** 第一期优先完成稳定的思考闭环，第二期再增强语义关联和长期洞察。

## 1.3 目标用户

- 经常使用 AI 讨论学习、职业、科技、社会或人生议题的人；
- 希望形成长期思想记录，但不愿维护复杂知识图谱的人；
- 重视隐私、出处、版本和数据可迁移性的用户；
- 需要把讨论成果导出为文章素材、研究笔记或个人档案的人。

## 1.4 产品成功指标

### 北极星指标

每周完成沉淀的有效思考空间数。一次“有效沉淀”至少包含：一轮讨论或一篇感思，以及一份用户查看或编辑过的纪要。

### 第一阶段指标

- 80% 的新用户可在三步内开始首个议题；
- 自动保存成功率不低于 99.9%；
- 纪要生成成功率不低于 98%；
- 90% 的重要纪要陈述可回溯到原始内容或标明为综合推断；
- 核心页面 75 分位交互响应低于 200ms（不含外部模型生成）；
- 用户可在 3 分钟内完成一个思考空间的导出；
- 删除请求、授权撤回与导出操作均有可审计状态。

## 1.5 范围边界

### 第一期：核心 MVP

- 账户与个人数据空间；
- 每日三类议题推荐及自建议题；
- 多模型选择、流式对话、分支与历史恢复；
- 旁注、重点标记、独立感思；
- 结构化纪要、引用回溯、基础思维导图；
- 标签与关键词搜索；
- Markdown、PDF、JSON 导出；
- 云端同步、本地草稿、备份与数据删除；
- 联网来源展示、模型用量与费用提示。

### 第二期：个人知识库增强

- 全文与语义混合搜索；
- 双向链接、相似和冲突观点建议；
- 思考时间轴、周报和月报；
- 跨议题观点聚合与变化分析；
- 用户自带 API Key；
- Word、PNG、SVG 增强导出；
- 多设备离线缓存和同步冲突处理增强。

### 当前不做

- 公开社区、关注、评论、点赞和议题广场；
- 多人实时协作；
- 语音通话或 AI 数字人；
- 自动代替用户公开发布内容；
- 复杂的手工知识图谱编辑器；
- 模型训练或微调；
- 将 AI 产物默认为用户观点。

# 2. 核心概念与用户旅程

## 2.1 核心对象

“思考空间”是主要工作单位。每个空间对应一个议题，可容纳多次会话、多模型分支、旁注、感思、资料、纪要和导图。同一议题可在不同时间重新讨论，支持观察用户观点是否变化。

## 2.2 主用户旅程

### 旅程 A：从每日议题开始

1. 用户打开“今日”；
2. 浏览今日热点、为你推荐、随机思想题；
3. 查看议题背景、推荐原因和信息来源；
4. 选择议题，编辑讨论目标；
5. 选择模型和是否联网；
6. 开始讨论并随手添加旁注或标记；
7. 点击“整理本次思考”；
8. 检查并编辑纪要与思维导图；
9. 保存、回顾或导出。

### 旅程 B：自建议题

用户输入一个问题，可补充已有观点、希望解决的问题、标签、资料和讨论深度。AI 可提出拆题、反例和引导问题，但未经确认不覆盖用户原文。

### 旅程 C：记录感思

用户可从全局入口或思考空间创建感思。感思可关联多个议题、会话、纪要和其他感思。AI 整理稿与用户原文分开保存，原文始终可恢复。

### 旅程 D：长期回顾

用户通过搜索、标签、时间线和“未解决问题”重新进入历史内容。系统可在授权后推荐相关旧观点，但所有关联建议均需用户确认。

# 3. 信息架构与页面设计

## 3.1 一级信息架构

- **今日**：每日议题、快速创建、继续思考、历史回顾。
- **思考空间**：讨论、感思、资料、纪要、思维导图。
- **知识库**：议题、对话、感思、纪要、标签、收藏、归档和搜索。
- **回顾**：时间轴、主题、未解决问题、观点变化、周期回顾。
- **导出与备份**：单项导出、批量导出、完整备份、恢复和任务历史。
- **设置**：个人资料、模型、授权、隐私、联网偏好、导出偏好和用量。

第一期主导航只突出“今日、知识库、回顾”；导出和设置置于个人菜单。

## 3.2 全局框架

桌面端采用左侧主导航、中间工作区、右侧上下文面板。右侧面板按场景显示旁注、引用、资料、标签或节点详情。移动端采用底部导航、单列内容和抽屉面板；对话输入固定在底部，纪要和导图可全屏查看。

## 3.3 今日首页

首页不是统计仪表盘，而是安静的思考入口。

- 顶部：日期、简短问候、自建议题、搜索、同步状态；
- 今日热点：标题、讨论价值、引导问题、来源数量和更新时间；
- 为你推荐：推荐原因、关联历史主题及授权提示；
- 随机思想题：问题、正反切入角度、“换一个”；
- 继续思考：未完成空间、未解决问题和久未回顾的重要议题。

系统必须解释推荐原因，不使用不透明的“猜你喜欢”。联网失败时显示最近一次成功内容及其真实日期，不伪装为当日热点。

## 3.4 创建议题

必填项只有议题标题。可选项包括动机、已有观点、目标问题、标签、参考资料、讨论深度和是否联网。AI 的优化、拆题、反例和事实前提检查都以候选建议呈现。

## 3.5 思考空间

顶部展示标题、状态、标签、收藏、最后保存时间和更多操作。状态为：未开始、讨论中、待整理、已沉淀、已归档。内部视图包括讨论、感思、资料、纪要和思维导图。

## 3.6 对话体验

顶部展示当前模型、联网状态、会话分支、上下文范围和用量。切换模型时支持：空白新分支、携带结构化摘要、携带选中消息。默认携带结构化摘要，并展示将发送的内容。

每条消息支持旁注、重点、观点、证据、疑问、结论、待核实、引用、加入纪要候选和复制。用户编辑已发送消息时创建新分支，不覆盖原历史。AI 联网回复在对应段落显示引用，并列出来源、发布日期和访问时间。

旁注默认只对用户可见。用户可选择仅保存、用于下一条消息、允许纪要使用或永不参与 AI 分析。

## 3.7 感思编辑器

支持标题、Markdown、自动保存、标签、关联、版本历史和 AI 整理建议。AI 可帮助梳理表达、寻找反例、比较过去观点和提出后续行动。用户原文与 AI 整理稿分别保存。

## 3.8 纪要与思维导图

生成前由用户选择对话分支、旁注、感思、资料、长度、语言和是否生成导图。纪要结构包括：背景、用户核心观点、观点变化、对话重点、正反理由、证据、结论、未解决问题和后续探索。

纪要采用左侧正文、右侧依据的分栏。用户可锁定章节、局部重新生成、比较版本并标记正式版本。没有直接依据的内容标注“综合推断”。

思维导图默认以议题为中心，一级节点为核心观点、支持理由、反对理由、证据资料、未解决问题、结论和后续探索。导图支持树形文本等价视图。导图与纪要共享来源结构但独立版本，修改时询问是否同步。

## 3.9 知识库与回顾

第一期采用统一搜索与分类列表。支持关键词、类型、日期、标签、模型、状态、收藏、归档、用户原文或 AI 内容筛选。搜索结果必须在上下文中打开。

回顾页展示近七天内容、常见主题、未解决问题、收藏但未继续的内容和随机历史感思。第二期增加时间轴、跨议题聚类和周期报告。

## 3.10 导出体验

用户选择范围、格式、是否含原始对话、私人旁注、来源、导图以及是否隐藏模型和费用。导出前显示隐私预览。大文件由后台任务生成。

JSON 使用带版本号的开放结构，保留实体、时间、关系、版本、模型和来源信息，但永不包含 API Key、登录凭据和内部安全字段。

# 4. 视觉与交互规范

## 4.1 设计气质

整体气质为安静、克制、可信和适合长时间阅读。视觉上更接近写作工具与研究笔记，而不是社交媒体或数据看板。避免高饱和渐变、过量卡片、连续奖励和制造焦虑的连续签到。

## 4.2 视觉系统建议

- 背景：中性浅灰或柔和近白；深色模式使用低眩光深灰；
- 主色：低饱和蓝绿色，用于主操作、选择和引用定位；
- 语义色：绿色表示已同步/已确认，琥珀色表示待核实，红色仅用于错误与危险操作；
- 正文：适合中文长文阅读的系统无衬线字体；纪要可选阅读型字体；
- 正文基准：桌面 16px/1.75，移动 16px/1.7；
- 圆角与阴影：轻量使用，主要依赖留白、分割线和层级；
- 最大正文行宽：约 720–800px，避免过长行；
- 动效：150–240ms，支持减少动态效果。

## 4.3 内容身份标识

用户原文、AI 回复、AI 整理稿、用户修订稿和联网来源必须通过标签、署名和样式共同区分，不能只依赖颜色。每项 AI 生成内容均展示模型和生成时间；综合推断有明确标识。

## 4.4 关键反馈

- 自动保存：保存中、已保存、离线待同步、同步冲突；
- AI 生成：流式进度、停止、重试、切换模型；
- 后台任务：等待、运行、成功、失败、取消和部分完成；
- 危险操作：说明影响范围并二次确认；
- 空状态：提供清晰下一步，不用虚假示例数据制造繁荣。

## 4.5 无障碍

- 完整键盘导航和明显焦点状态；
- 正文与控件满足 WCAG 2.2 AA 对比度目标；
- 所有状态不只依赖颜色；
- 思维导图提供树形文本视图；
- 支持浏览器缩放至 200%；
- 生成状态通过可访问的实时区域播报；
- 图标按钮有可读名称；
- 动效遵循系统减少动态效果设置。

# 5. 系统架构与技术选型

## 5.1 架构原则

第一期采用模块化单体：开发、部署和事务处理简单，同时以内部接口隔离身份、议题、对话、纪要、搜索、导出和模型网关。流量增长后再拆分高负载任务。

## 5.2 推荐技术栈

- Web：Next.js、React、TypeScript；
- 关系数据库：PostgreSQL；
- 对象存储：导出、备份和未来附件；
- 缓存与队列：Redis 兼容服务；
- 搜索：第一期 PostgreSQL 全文检索，第二期 pgvector；
- 本地缓存：浏览器 IndexedDB，保存草稿与待同步操作；
- 部署：支持区域化部署、HTTPS、私有对象存储和托管数据库。

## 5.3 模块边界

1. 身份认证与用户空间；
2. 议题与思考空间；
3. 对话与模型调用；
4. 旁注、感思和标记；
5. 纪要与思维导图；
6. 知识库与搜索；
7. 联网检索与每日推荐；
8. 导出、备份与恢复；
9. 用量、费用与配额；
10. 授权、安全与审计。

## 5.4 后台任务

每日议题、滚动摘要、纪要、导图、PDF、完整备份、索引、向量和数据清理均通过后台任务执行。任务具备进度、幂等、有限重试、失败原因、取消和超时处理。

# 6. 数据模型

## 6.1 核心实体

- **User / UserPreference / ConsentRecord**：账户、偏好和授权历史；
- **Topic / ThinkingSpace**：议题及其工作空间；
- **Conversation / Message / Citation**：会话分支、消息和联网引用；
- **Annotation / Reflection / ReflectionVersion / MessageMark**：旁注、感思、版本和标记；
- **ContentLink**：支持、反对、延伸、相似、冲突和引用等关系；
- **Summary / SummaryVersion / SummaryClaim**：纪要、版本及依据映射；
- **MindMap / MindMapNode**：导图及节点；
- **ExportJob / BackgroundJob / UsageRecord**：导出、任务和用量。

所有用户内容实体包含 `user_id`、创建时间、更新时间和删除状态。服务端从认证上下文确定用户身份，不接受客户端自由指定所有者。

## 6.2 版本策略

- 已发送消息不可原地覆盖，编辑产生新分支；
- 感思保存用户原文、AI 整理稿和用户修订版本；
- 纪要支持多版本、锁定章节和正式版本；
- 导图与纪要独立版本；
- AI 建议的内容关联处于待确认状态；
- 删除采用可恢复期和最终清理期，立即彻底删除另行确认。

## 6.3 内容关系

ContentLink 记录来源类型与 ID、目标类型与 ID、关系类型、创建者、置信度和确认状态。AI 推断出的“相似”“冲突”或“支持”不能自动等同于用户认可。

# 7. AI、联网检索与推荐

## 7.1 统一模型网关

业务模块通过统一网关调用模型。网关负责统一请求、流式格式、能力登记、上下文检查、用量计费、超时重试、限流、模型降级、工具调用、脱敏和用户 Key 路由。

每个模型登记流式输出、工具调用、联网、结构化输出、上下文长度、输入输出类型、价格、区域限制和可用状态。界面只展示真实可用组合。

## 7.2 上下文组装

优先级为：当前议题与目标、最近消息、用户选择内容、分支摘要、已授权旁注和感思、已授权资料、已授权历史内容。调用前展示上下文概览。

长会话通过滚动摘要压缩，摘要保存对应消息范围；固定的重要内容优先保留，不静默丢弃。

## 7.3 纪要生成

流程为：确定输入范围、提取结构、去重、识别关系、匹配依据、生成纪要、标注推断、生成导图、保存参数和版本。

约束包括：不把 AI 观点写成用户观点；不将未核实网页内容写成事实；不臆造观点变化；没有变化时明确说明；重新生成不覆盖锁定章节。

## 7.4 每日议题

热点议题从多个可靠来源获取候选，聚合同一事件，检查发布时间与事件日期，去除重复和低可信内容，再生成讨论问题并保留来源。

个性化议题仅在授权后使用标签、未解决问题、近期主题和已确认摘要。优先使用结构化元数据，不默认读取全部原始对话。

随机思想题来自维护过的议题种子库，具有近期去重、主题多样性、敏感偏好和负反馈机制。

# 8. 隐私、安全与数据治理

## 8.1 数据保护

- 全程 HTTPS；
- 数据库和对象存储静态加密；
- API Key 独立应用层加密并与业务数据分离；
- 日志默认不记录对话正文；
- 错误追踪脱敏；
- 私有对象访问与短时下载链接；
- 导出文件自动过期；
- 管理员默认不可直接浏览用户原文。

## 8.2 授权控制

系统必须能说明每次模型调用发送给哪家服务、哪个模型、哪些内容类型、是否含历史或旁注以及是否联网。授权可按全局、议题和单次调用调整，撤回后停止后续使用并清理相应索引。

## 8.3 提示注入防护

网页和外部资料均视为不可信数据。外部文字不得修改系统指令，资料内容与控制指令分离；工具调用采用白名单；外部页面不能触发账户、导出或删除；所有状态变更由用户明确确认。

## 8.4 删除与备份

普通删除进入短期恢复区，到期后清理主库、索引、向量、关联和导出文件，并按备份周期最终过期。“立即彻底删除”要求二次确认并说明备份最长清理期限。

---

# 9. 异常、离线与同步

外部服务失败不影响用户访问、编辑和导出已有内容。

- 模型超时：保留用户问题、已生成片段和草稿，可重试或换模型；
- 联网失败：保留上次有效议题并显示真实日期；
- 纪要失败：保留已完成阶段，允许从失败点重试；
- 离线：可访问缓存、写感思、保存草稿，联网后同步；
- 同步冲突：长文本保留两个版本，不静默覆盖；
- 配额不足：提示原因、成本和可用低成本模型；
- 来源失效：保留引用快照元数据并标记当前不可访问。

写操作使用客户端生成的幂等键，避免网络重试产生重复消息或内容。

# 10. 功能验收标准

## 10.1 今日议题

- 每个用户时区每天生成三类议题；
- 热点议题展示至少两个可访问来源或明确说明来源不足；
- 推荐内容包含生成时间、事件日期和推荐理由；
- 用户可关闭个性化或排除具体议题；
- 失败时不把旧议题标记成当天内容。

## 10.2 对话

- 用户可选择模型、联网状态和上下文范围；
- 流式回复可停止，已接收内容不丢失；
- 编辑历史消息产生新分支；
- 切换模型前展示携带的上下文；
- 旁注默认不发送给 AI；
- 刷新页面后可恢复会话和输入草稿。

## 10.3 感思与纪要

- 用户原文与 AI 整理稿可独立查看和恢复；
- 纪要输入范围由用户明确选择；
- 重要陈述能定位原始依据或标记为综合推断；
- 锁定章节在局部重生成后保持不变；
- 纪要和导图保留版本；
- 导图提供等价树形文本。

## 10.4 搜索与导出

- 关键词搜索支持标题、正文、标签和类型筛选；
- 结果可定位到议题内原始上下文；
- Markdown、PDF、JSON 导出成功并保持中文可读；
- JSON 可校验版本号和关系完整性；
- 导出不包含密钥、令牌或内部安全字段；
- 大任务可查看进度、取消和重试。

## 10.5 隐私与删除

- 所有资源访问均验证所有者；
- 用户可查看和撤回历史内容授权；
- 单次模型请求可查看上下文概览；
- 删除流程清理索引、关系和导出；
- 安全日志不含完整对话正文。

# 11. 测试策略

## 11.1 自动化测试

- 单元测试：权限判定、上下文选择、纪要结构解析、费用计算、导出映射；
- 集成测试：数据库事务、模型网关适配、队列幂等、对象存储权限；
- 契约测试：各模型流式事件、结构化输出和错误映射；
- 端到端测试：创建议题、讨论、旁注、纪要、导图、搜索、导出和删除；
- 安全测试：越权访问、提示注入、下载链接、密钥泄漏和日志脱敏；
- 可访问性测试：键盘、焦点、语义结构、对比度和屏幕阅读器；
- 性能测试：长会话、大型纪要、并发流式连接和导出任务。

## 11.2 AI 质量评估

建立去标识化评测集，覆盖哲学、科技、生活和社会议题。评估：用户观点归属准确率、依据覆盖率、来源一致性、未解决问题召回、观点变化误报率和中文表达质量。

每次更换模型、提示模板或纪要流程时运行回归评测。线上不自动使用私人内容构造评测集，除非用户明确授权。

## 11.3 上线门槛

- P0/P1 缺陷为零；
- 核心端到端路径通过；
- 跨用户数据隔离测试全部通过；
- 备份恢复演练通过；
- PDF/Markdown/JSON 样例经人工检查；
- 模型不可用、网络断开和队列积压的降级演练通过；
- 隐私说明、授权文案和删除流程完成审查。

# 12. 分期路线图

## 阶段 0：产品与技术基线（2 周）

- 设计系统、数据模型和模型网关协议；
- 认证、权限、授权和审计框架；
- 每日议题来源策略与评测样本；
- 交互原型和可用性验证。

退出条件：主流程原型通过 5–8 名目标用户测试，权限模型和导出结构评审通过。

## 阶段 1：核心记录闭环（4–6 周）

- 账户、议题、思考空间；
- 单一平台下的 2–3 个模型；
- 流式对话、分支、草稿；
- 旁注、标记、感思；
- 云端保存和基础本地缓存。

退出条件：可稳定完成“建题—对话—记录感思”，自动保存和恢复达到目标。

## 阶段 2：沉淀与导出（3–4 周）

- 纪要、依据回溯、版本和锁定章节；
- 基础思维导图和树形视图；
- Markdown、PDF、JSON；
- 后台任务、进度和失败恢复。

退出条件：核心闭环完整，导出结构和中文排版通过验收。

## 阶段 3：每日议题与知识库（3–4 周）

- 三类每日议题；
- 联网引用与来源治理；
- 关键词搜索、标签和回顾；
- 用量、配额和成本提示。

退出条件：每日任务稳定，来源可追溯，MVP 可邀请小范围用户。

## 阶段 4：知识增强（后续）

- 语义搜索、双向关联和观点变化；
- 自带 API Key；
- 周月回顾、Word 和图像导出；
- 更强离线和多设备冲突处理。

路线图为建议估算，实际进度取决于团队规模、模型供应商接入、安全与合规范围。优先级以可靠保存和数据控制高于新增智能功能。

# 13. 风险与控制

## 13.1 AI 错归用户观点

风险：纪要把 AI 建议写成用户立场。  
控制：按消息角色提取；重要陈述绑定依据；无依据标记推断；用户确认正式版本。

## 13.2 联网信息失真或过期

风险：热点议题建立在错误、重复或旧消息上。  
控制：多来源聚合；区分发布日期与事件日期；标注访问时间；来源不足时降级或不生成。

## 13.3 隐私范围不清

风险：私人旁注或历史内容被意外发送。  
控制：默认排除；请求前显示上下文概览；授权可撤回；日志脱敏；供应商清晰标识。

## 13.4 模型成本失控

风险：长对话、重复生成和高价模型带来不可控成本。  
控制：滚动摘要、缓存、分级模型、配额、费用提示、后台任务限流和用户预算上限。

## 13.5 供应商依赖

风险：模型接口变化、限流或区域不可用。  
控制：统一网关、能力登记、契约测试、降级模型和供应商健康监控。

## 13.6 产品过度复杂

风险：知识关联和导图让记录变成维护负担。  
控制：默认自动整理、渐进披露；第一期以列表和搜索为主；复杂关联需用户主动进入。

## 13.7 数据丢失或同步冲突

风险：生成中断、离线或多设备覆盖内容。  
控制：本地草稿、流式片段持久化、幂等写入、版本历史、冲突副本和备份恢复演练。

# 14. 产品决策记录

| 决策 | 结论 | 原因 |
|---|---|---|
| 产品形态 | 个人优先，可扩展多用户 | 快速验证同时避免未来数据隔离重构 |
| 主组织方式 | 议题与思考空间 | 比会话列表更适合长期沉淀 |
| 模型策略 | 混合接入 | 兼顾易用、选择和成本自主权 |
| 思考过程 | 可读推理摘要 | 保留价值且不依赖隐藏思维链 |
| 个性化 | 明确授权后使用 | 尊重隐私并提高可解释性 |
| 架构 | 模块化单体 | 降低第一期复杂度，保留拆分边界 |
| 搜索 | 关键词先行，语义后置 | 先保证可预测、可解释和低运维成本 |
| 导出 | Markdown/PDF/JSON 优先 | 覆盖阅读、分享与迁移 |
| 社区 | 当前不做 | 集中验证个人思考闭环 |

# 15. 开放问题与默认假设

以下事项不阻塞第一期设计，但进入实施计划前需要产品负责人最终确认：

1. 品牌名“思屿”是否正式采用；当前仅作为工作名称。
2. 第一批具体模型供应商与目标市场的数据处理区域。
3. 热点来源白名单、内容版权策略及是否保存网页摘录。
4. 免费额度、订阅或按量计费的商业模式。
5. 账户删除的恢复期和备份最长清理周期。
6. 第一版是否支持网页链接之外的 PDF 或文件资料；当前基线为不支持复杂附件。

默认假设：第一版为中文优先的响应式 Web 产品；平台负责模型费用；用户数据不用于模型训练；不公开分享内容；服务运行地区和合规文本在上线前根据目标市场确定。

- **占位符检查：** 无 TBD、TODO 或未完成章节；开放问题均给出不阻塞实施的默认假设。
- **一致性检查：** 功能范围、信息架构、数据模型、架构与路线图一致；自带 API Key、语义搜索、Word/PNG/SVG 明确位于第二期。
- **范围检查：** 当前文档聚焦个人思考闭环，不包含社区与多人协作。
- **歧义检查：** “思考过程”明确定义为可读推理摘要与观点演变，不等同于模型隐藏思维链；“混合存储”明确定义为云端正式数据加本地草稿和待同步操作。
