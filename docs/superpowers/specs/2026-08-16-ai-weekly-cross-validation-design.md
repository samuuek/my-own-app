# 思屿 AI 周报与多模型交叉验证设计

## 目标

在思屿中新增“AI 周报”顶层页面，自动聚合最近 7 天可核验的 AI 官方消息，并允许用户通过 DeepSeek、通义千问和 Kimi 的免费网页版分别分析同一批材料。系统以官方原文为事实底座，将模型输出拆分为共识、分歧和待核实推断。

## 核心原则

- 官方来源决定事件是否发生，模型不承担事实认证。
- 三个模型接收完全相同的材料与问题，保证比较基础一致。
- 模型多数意见不自动升级为事实。
- 所有已确认消息必须保留官方原文 URL、机构与发布日期。
- 无法关联到原始消息的模型观点标记为“模型推断”。
- 不读取或保存任何模型网站的账号、密码、Cookie、Token 或登录状态。

## 页面信息架构

顶部导航新增“AI 周报”，URL hash 为 `#weekly`。页面由四部分组成：

1. 周报页首：标题“这一周，AI 又向前走了哪里？”，显示统计周期、最近更新时间和“刷新官方消息”。
2. 本周关键进展：从当前数据中按时间与来源完整度展示最多 3 条重点消息，不由模型凭空生成。
3. 官方消息时间线：展示最近 7 天消息，支持按“全部、模型、产品、研究、开源、政策”筛选。
4. 多模型交叉验证：显示 DeepSeek、通义千问和 Kimi 三个分析槽位，以及结果对照区。

每条官方消息展示机构、标题、发布日期、中文简述、分类、原文链接和“为什么值得关注”。中文简述和关注理由在没有模型结果时采用官方摘要的保守转换；不得加入官方材料未表达的效果、排名或影响判断。

## 官方来源聚合

### 来源注册表

后端维护显式来源白名单，首版包含：

- OpenAI News
- Anthropic News
- Google DeepMind Blog
- Microsoft AI Blog
- Meta AI Blog
- Hugging Face Blog

每个来源记录机构名、官方域名、订阅或列表 URL、默认分类和解析器类型。只接受 HTTPS，抓取结果的最终链接必须仍属于注册的官方域名。

### 数据获取

后端提供：

- `GET /api/weekly`: 返回缓存中的最近 7 天消息、来源状态和更新时间。
- `POST /api/weekly/refresh`: 逐个刷新官方来源，规范化、去重、写入缓存后返回最新周报。

刷新不是定时后台任务。页面打开时读取缓存；缓存超过 6 小时后，前端提示可以刷新，但不在用户未操作时主动访问外网。用户点击刷新后才执行网络抓取。

首版支持 RSS/Atom 与结构固定的官方列表页面。单个来源解析失败不导致整次刷新失败；返回该来源失败状态，并继续保存其他来源的成功结果。

### 规范化与去重

消息统一为：

```ts
type WeeklyItem = {
  id: string
  sourceId: string
  organization: string
  title: string
  url: string
  publishedAt: string
  category: '模型' | '产品' | '研究' | '开源' | '政策'
  summary: string
  significance: string
}
```

`id` 由规范化 URL 生成。相同规范化 URL 只保留一条；标题相同但 URL 不同的消息不自动合并。只保留当前时间向前 7 个完整自然日内的消息，未来日期视为来源错误并丢弃。

### 本地缓存

SQLite 新增周报消息、来源刷新状态和模型分析三类数据。刷新成功时更新对应来源的消息；来源失败时保留其上次成功缓存。页面必须显示数据更新时间和失败来源，不能用旧缓存伪装为刚刚更新。

## 免费网页版模型往返

### 支持服务

```ts
type WeeklyAnalyst = 'deepseek-web' | 'qwen-web' | 'kimi-web'
```

对应官网：

- DeepSeek：`https://chat.deepseek.com/`
- 通义千问：`https://www.qianwen.com/`
- Kimi：`https://www.kimi.com/`

模型槽位不显示“已登录”或“已连接”，只显示“网页版可用”“等待分析”或“已导入”。

### 统一提示词

用户点击某个模型的“打开并分析”后，思屿按固定顺序复制最近 7 天的同一份消息清单。每条材料包含稳定编号、机构、日期、标题、官方摘要、原文 URL。提示词要求模型只返回以下 Markdown 结构：

1. 三项关键进展，每项引用消息编号。
2. 趋势判断，每项引用至少两个消息编号。
3. 可能被高估的进展及理由。
4. 尚待核实的问题。
5. 一句总结。

提示词明确禁止添加清单之外的“最新消息”，禁止把模型自身知识当作来源。复制失败时展示可手动复制的完整提示词；新标签页被拦截时展示普通官网链接。

### 回答导入

用户复制网页回答，返回思屿点击“粘贴分析”。系统读取剪贴板并展示可编辑预览；权限失败时提供空白手动粘贴框。空内容或超过 200,000 字的内容不得保存。保存时记录模型 ID、分析周期、材料集合指纹、原始 Markdown 和更新时间。

如果官方消息集合在某次分析后发生变化，旧分析显示“基于上一版材料”，不得与新材料的分析直接合并。

## 交叉验证

首版不再调用第四个模型做汇总，也不尝试用自然语言模型自动裁决。系统使用提示词中的固定 Markdown 标题和消息编号进行确定性提取：

- 共识：至少两个模型在对应章节引用同一消息编号。
- 三模型共识：三个模型均在“关键进展”或“趋势判断”引用同一编号。
- 分歧：同一消息编号出现在某模型的“关键进展”，同时出现在另一模型的“可能被高估”。
- 单模型观察：只有一个模型引用的判断。
- 待核实：模型放入“尚待核实的问题”，或内容未引用任何消息编号。

对照结果始终展示原始模型文本入口。解析失败时保留原文并显示“格式未识别”，允许用户编辑后重新解析，不丢失回答。

## 交互状态

- 首次使用且无缓存：展示来源说明和“获取本周消息”，不展示虚构示例新闻。
- 有缓存且新鲜：直接展示内容。
- 有缓存但超过 6 小时：展示“上次更新于……”和刷新建议。
- 部分来源失败：展示成功消息，并在页首列出未更新来源。
- 全部来源失败：保留上次成功结果；若从未成功，则展示明确空状态。
- 模型分析不足两个：展示各自结果，不生成“共识”标签。
- 分析材料版本不一致：按版本分组，不跨版本比较。

## 安全与隐私

- 官方抓取只访问来源白名单中的 HTTPS 地址，并限制响应体大小、超时和重定向后的域名。
- HTML/RSS 只作为不可信文本解析，不执行其中的脚本。
- 发送给网页版模型的材料仅包含公开官方消息，不包含用户议题、私人旁注、知识库或对话历史。
- 仅在用户明确点击时读写剪贴板和打开外部网页。
- 模型账号信息始终由浏览器和对应网站管理。

## 测试与验收

### 自动化测试

- 导航可进入 `#weekly`，刷新后能恢复页面。
- 7 天边界、未来日期丢弃、URL 去重和分类过滤正确。
- 白名单、HTTPS、响应体大小、超时与重定向域名得到约束。
- 单个来源失败不会覆盖其旧缓存，也不阻断其他来源。
- 三个模型收到同一材料集合与同一结构化提示词。
- 剪贴板失败、弹窗拦截和手动粘贴降级可用。
- 回答保存材料指纹；旧版本不会参与新版本交叉验证。
- 共识、三模型共识、分歧、单模型观察和待核实的确定性规则正确。
- 无编号或格式错误回答保留原文并显示解析状态。

### 浏览器验收

- 桌面完成官方消息获取、分类筛选、三模型任一往返、回答预览和对照查看。
- 在 390 × 844 移动视口检查导航、时间线、模型槽位和对照区无横向溢出。
- 模拟单来源失败、全部失败、旧缓存、剪贴板拒绝和弹窗拦截。
- 页面没有把模型观点标记为官方事实，所有官方消息的原文链接可见。
- 控制台无相关错误或警告。

## 非目标

- 不后台自动登录或操作任何模型网站。
- 不抓取模型网站的对话内容。
- 不使用免费网页账号作为非官方 API。
- 不自动发布、分享或发送周报。
- 不对全网新闻做开放式搜索；首版只聚合显式官方白名单。
- 不用模型投票替代官方来源核验。
