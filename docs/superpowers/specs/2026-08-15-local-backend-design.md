# 思屿本机个人版后端设计

## 目标

把现有依赖 Vite 中间件和浏览器 localStorage 的原型升级为可独立运行的本机应用：所有思考数据由本地后端可靠保存，模型密钥只存在于后端环境变量，桌面快捷方式仍可一键启动。

## 范围

第一版为单用户、无登录、本机访问。后端仅监听 `127.0.0.1`，使用 SQLite 保存议题、空间、消息、私人旁注、感思、资料、纪要、导图和设置，并提供 JSON 备份与恢复。暂不加入云同步、多人协作、对象存储和后台队列。

## 架构

- 前端：保留 React + Vite，通过 `/api` 调用后端。
- 后端：Node.js 模块化单体，使用内置 HTTP 服务和 `node:sqlite`，不引入原生第三方数据库依赖。
- 开发：Vite 将 `/api` 代理到独立后端；`npm run dev` 同时启动前后端。
- 生产：后端可托管前端构建产物，为桌面快捷方式提供单一地址。
- 数据：默认数据库位于 `data/siyu.db`，运行时自动建表和填充初始议题。

## 数据模型

- `topics`：议题基本信息、状态、创建和更新时间。
- `workspaces`：一个议题对应一个思考空间，保存私人旁注、感思、资料、纪要、导图与所选模型。
- `messages`：空间内按顺序保存用户和 AI 消息，记录模型与生成时间。
- `settings`：非敏感应用设置。API Key 明确禁止写入数据库。

采用文本 ID、ISO 时间和 JSON 字段。数据访问封装在仓储层，后续可替换为 PostgreSQL。

## API

- `GET /api/health`：服务和数据库状态。
- `GET /api/models`、`POST /api/chat`：模型清单与统一模型调用；聊天成功后可原子保存用户和 AI 消息。
- `GET/POST /api/topics`、`GET/PATCH/DELETE /api/topics/:id`：议题管理与搜索。
- `GET/PATCH /api/workspaces/:topicId`：空间内容读取与自动保存。
- `GET/POST /api/workspaces/:topicId/messages`：消息读取与新增。
- `GET /api/backup`、`POST /api/restore`：版本化 JSON 备份与恢复。

所有写接口校验类型、长度与允许字段；错误响应统一为 `{ error, code }`，不返回堆栈、密钥或供应商原始敏感正文。

## 前端接入

首次打开空间时读取后端；若浏览器中存在旧版 localStorage 数据且后端空间为空，则迁移一次。编辑旁注、感思等内容采用短延迟自动保存，并展示“保存中 / 已保存 / 保存失败”。消息发送由后端统一写入，避免刷新后丢失。

## 安全与恢复

- 服务仅绑定回环地址；限制 JSON 请求体大小。
- API Key 只从 `.env` / 进程环境读取，不写日志、响应、备份或前端存储。
- SQLite 使用外键和 WAL；关键恢复操作使用事务。
- 恢复前校验备份版本和结构；默认以合并方式导入，避免静默覆盖。

## 验证

单元测试覆盖建表、增删改查、搜索、消息顺序、备份恢复、校验和密钥不泄露；集成测试通过真实临时 SQLite 数据库调用 HTTP API；最后运行前端测试、类型检查和生产构建。
