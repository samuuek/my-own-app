# Vercel + Neon 云端部署设计

日期：2026-08-16

## 目标

将现有的“samuel的工作台”部署为仅本人可访问的云端网站，使用户可以通过手机、平板或其他电脑访问同一份云端数据，同时保留现有桌面版和本地 SQLite 数据不变。

部署必须使用免费套餐：Vercel Hobby、Neon Free 和 Vercel Blob 的 Hobby 免费额度。若任何步骤要求升级套餐、绑定支付方式或产生费用，部署流程必须停止并请求用户确认。

## 已确认范围

- 使用 Vercel Hobby 托管网页和 API。
- 使用 Neon Free 保存结构化数据。
- 使用 Vercel Blob 私有存储保存未来上传的书籍 PDF 和封面。
- 使用 Vercel Authentication 保护页面和 API，仅允许用户登录自己的 Vercel 账号后访问。
- 将当前桌面 SQLite 数据一次性复制到云端。
- 不删除、不覆盖、不改变本地 SQLite 数据；桌面版继续独立使用本地数据。
- 云端上线后，各浏览器设备共享 Neon 中的数据；桌面版与云端版不会自动双向同步。
- 网页版隐藏“打开本地目录”“保存并退出桌面程序”等只适用于本机的操作。

## 架构

### 网页与 API

保留现有 React/Vite 前端和 API 调用契约。Fastify API 适配 Vercel Node.js Functions，浏览器继续通过同源 `/api/*` 请求数据。正式部署由 Vercel 提供 HTTPS、CDN、函数运行环境和身份验证保护。

### 数据访问边界

定义统一的存储接口，使前端和业务服务不依赖具体数据库实现：

- 桌面运行模式继续使用现有 SQLite 存储实现。
- 云端运行模式使用异步 Postgres 存储实现，并通过 Neon 的池化连接字符串访问。
- API 层根据运行环境选择实现，不把数据库凭据发送到浏览器。

现有同步 SQLite 业务代码不得直接复用于异步 Postgres 请求。云端实现应以相同输入输出契约提供集合操作、仪表盘聚合、目标/日期/计时、反思、回收站和设置等功能。

### 文件存储

- 桌面模式继续使用本地附件目录。
- 云端模式使用 Vercel Blob 私有存储。
- 数据库只保存 Blob 路径、文件名和内容类型，不保存公开访问 URL。
- 下载请求通过已受身份验证保护的 API 获取并转发私有文件。
- 当前本地附件数量为 0，因此首次迁移无需上传文件。

### 身份与隐私

项目启用 Vercel Authentication，并覆盖生产部署及预览部署。所有页面和 `/api/*` 路由都处在相同保护边界内。应用本身不新增第二套密码系统，也不在代码库中保存数据库连接串、Blob Token 或其他密钥。

## 数据迁移

1. 在迁移前对本地 SQLite 执行完整性检查和 WAL checkpoint。
2. 创建一个新的可恢复备份，记录备份文件位置、大小和时间。
3. 在 Neon 临时分支应用 Postgres 架构迁移。
4. 验证所有表、约束、索引和默认值。
5. 从只读 SQLite 快照导出结构化记录；按依赖顺序写入临时分支。
6. 对每个集合比对记录数量，并抽查设置、今日计划、重要日期、长期目标和计时记录。
7. 只有临时分支验证通过后，才将架构和数据应用到 Neon 主分支。
8. 任一验证失败时停止部署，保留本地备份和 Neon 临时分支用于排查，不修改正式数据。

迁移是一次性复制。完成后，本地 SQLite 和云端 Postgres 成为彼此独立的数据源。

## 云端兼容行为

- 本地路径、打开文件夹、退出桌面进程等能力在云端返回“此功能仅适用于桌面版”，并在界面上隐藏主要入口。
- Neon 或 Blob 暂时不可用时，API 返回可识别的错误；前端保留当前缓存并显示重试提示，不能用空数组覆盖用户已经看到的数据。
- 写操作应在事务中完成；涉及多个记录的转换、计时结束和计划完成必须保持原子性。
- Serverless 连接使用池化连接串，避免每次请求创建过多数据库连接。
- 云端不运行依赖常驻进程的自动备份定时器；恢复能力由 Neon 的 Free 恢复窗口和应用导出功能承担。

## 免费额度约束

- Vercel 项目固定在 Hobby 计划。
- Neon 项目固定在 Free 计划，并启用空闲休眠。
- Blob 使用 Hobby 免费额度和私有存储。
- 不启用 Pro 试用、不购买域名、不添加付费监控或其他付费集成。
- 若免费额度耗尽，允许服务暂停，不能自动升级或产生超额账单。

## 测试与验收

### 自动化检查

- SQLite 桌面模式现有测试必须继续通过。
- 为 Postgres 存储契约、迁移映射、云端专用路由和错误处理添加测试。
- 构建、类型检查、代码规范、单元测试、集成测试和静态产物测试必须通过。
- Vercel 预览部署通过后才允许生产部署。

### 迁移验收

- 本地数据库完整性检查为 `ok`。
- 本地备份可读取，且文件大小大于 0。
- SQLite 与 Neon 的每类结构化记录数量一致。
- 关键设置、今日计划、重要日期、长期目标和当前计时状态抽查一致。

### 线上验收

- 未登录访问会进入 Vercel 登录保护。
- 登录后电脑和手机布局正常，无横向溢出或阻塞性错误。
- 能查看迁移数据、新增任务、编辑目标、完成计划和操作计时器。
- 刷新页面以及重新登录后，新数据仍然存在。
- 私有文件上传/读取路径通过测试，即使首次迁移没有附件。
- 线上函数构建日志和运行时错误日志无未处理错误。

## 上线与回滚

先创建受保护的预览部署并完成端到端验收，再将同一构建提升为生产部署。若生产验证失败，立即恢复到上一成功部署；数据库变更通过 Neon 分支和恢复窗口回退。桌面应用和本地 SQLite 始终作为不受云端发布影响的可用版本保留。

## 完成标准

用户收到一个受 Vercel 登录保护的生产网址；该网址在电脑和手机上可用，显示已迁移的数据，写入后可持久保存，并且 Vercel、Neon、Blob 均处于免费套餐。原桌面快捷方式、图标、本地数据和本地功能保持可用。
